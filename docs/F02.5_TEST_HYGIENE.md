# F02.5 — سلامت اجرای تست: cwd و temp ویندوز

**وضعیت:** VERIFIED · **تاریخ:** 2026-10-29 · **دامنه:** F-09، F-10 (فقط `tests/`، `.gitignore` و مستندات)

## English summary

`test_deploy.py::test_check_local_files` built its path from the implicit working directory, so it
failed from `backend/`. It now uses the real repo root (`Path(__file__).resolve().parents[1]`).

The Windows temp failure was a dead `pytest-of-<user>/pytest-current` **directory symlink**: pytest's
`cleanup_dead_symlinks` calls `Path.unlink()` on it, which Windows refuses with `WinError 5`, so every
run after a retention cleanup died at session end — and the same failure inside `getbasetemp()` would
take down any test that asked for `tmp_path`. Reproduced on this machine: the link was present, the
target gone, and `pytest tests/test_backup.py` exited 1 with `PermissionError` *after* all 7 tests
passed. The fix gives every run a private temp root (`PYTEST_DEBUG_TEMPROOT` → `gi-pytest-<pid>-*`,
deleted on exit), so the shared root and its symlink are never touched and parallel runs cannot
collide. `--basetemp` is no longer needed locally (CI keeps its explicit flag, which still wins).
Evidence: `pytest tests -q` **1482 passed / 1 skipped** from `backend/`, **1483 passed / 1 skipped**
from the repo root, repeated and parallel runs exit 0 with the poisoned link still in place, `ruff`
clean. The PG lane was not re-run for this change (it is cwd/temp-only; see limits).

## ۱) F-09 — تست وابسته به cwd

**علامت:** از ریشهٔ مخزن `5 passed`، از `backend/` یک فِیل:

```
E  AssertionError: assert ['docker-compose.yml', … '.env.example'] == []
```

**علت ریشه‌ای:** تست `check_local_files(Path("."))` را صدا می‌زد؛ `Path(".")` همان cwd است، پس از
`backend/` شش فایل لازم «گمشده» گزارش می‌شد.

**اصلاح:** ریشه از خود فایل تست ساخته می‌شود (نه cwd، نه یک ثابت مطلق):

```python
root = Path(__file__).resolve().parents[1]
missing = check_local_files(root)
```

`scripts/deploy_vps.py` دست نخورد: `Path(".")` در `main()` رفتار واقعی CLI است (اجرا از ریشهٔ مخزن).

## ۲) F-10 — `pytest-current` ویندوز

**علامت:** پس از چند اجرا/اجرای موازی، `PermissionError: [WinError 5] …\pytest-of-<user>\pytest-current`
و فِیل/خطای کاذب در انتهای session.

**بازتولید روی همین ماشین:**

```
pytest tests/test_backup.py -q     → 7 passed … سپس
PermissionError: [WinError 5] Access is denied:
  'C:\Users\hamid\AppData\Local\Temp\pytest-of-hamid\pytest-current'
exit code 1
```

**علت ریشه‌ای (نه علامت):** pytest در ریشهٔ مشترک `pytest-of-<user>` دو چیز می‌سازد: پوشهٔ شماره‌دار
`pytest-N` و symlink دایرکتوری `pytest-current` به آخرین آن. retention (پیش‌فرض: نگه‌داشتن ۳ اجرا)
پوشه‌های قدیمی را حذف می‌کند و `pytest-current` را «مرده» می‌گذارد. در
`_pytest/pathlib.py::cleanup_dead_symlinks` حذف با `Path.unlink()` انجام می‌شود و `os.unlink` ویندوز
روی symlink دایرکتوری `WinError 5` می‌دهد (حذف آن نیاز به `rmdir` دارد). این تابع هم در
`cleanup_numbered_dir` (پایان session / ساخت basetemp) صدا زده می‌شود، پس خطا هم به fixture
`tmp_path` و هم به `pytest_sessionfinish` می‌رسد. `--basetemp` فقط چون ریشهٔ مشترک را دور می‌زند
mask می‌کند — همان چیزی که نقشه به‌عنوان «workaround تشخیصی، نه اصلاح» رد کرده است.

**اصلاح:** هر اجرا ریشهٔ temp اختصاصی خودش را می‌گیرد و در exit پاک می‌شود:

```python
_OWN_TEMPROOT = Path(tempfile.mkdtemp(prefix=f"gi-pytest-{os.getpid()}-"))
os.environ.setdefault("PYTEST_DEBUG_TEMPROOT", str(_OWN_TEMPROOT))
```

`PYTEST_DEBUG_TEMPROOT` در `getbasetemp()` به‌صورت lazy خوانده می‌شود، پس تنظیم آن در import
conftest به‌موقع است. `--basetemp` صریح همچنان اولویت دارد (مسیر CI). پاک‌سازی: symlink
`pytest-current` با `rmdir` (ویندوز) و سپس `shutil.rmtree(..., ignore_errors=True)` در `atexit`.

**تست محافظ:** `tests/test_temp_isolation.py` — وقتی `--basetemp` داده نشده، `tmp_path` باید داخل
ریشهٔ اختصاصی همان pid باشد؛ وقتی داده شده، داخل همان مسیر صریح.

**هزینه/محدودیت آگاهانه:** چون ریشه در پایان هر اجرا حذف می‌شود، artifactهای `tmp_path` یک اجرای
فِیل‌شده برای post-mortem نمی‌مانند (در pytest پیش‌فرض ۳ اجرای آخر می‌ماند). مسیرها در خروجی
خود pytest چاپ می‌شوند و هر تست می‌تواند دوباره اجرا شود؛ در عوض هیچ ریشهٔ مشترکی برای خراب‌شدن
باقی نمی‌ماند.
